## 一、项目背景与选题说明

### 1.1 项目背景

当前校园二手交易市场存在以下问题：
- **信息分散**：交易信息散落在各个QQ群、微信群，难以集中查找
- **发布繁琐**：需要手动输入大量商品信息，耗时费力
- **匹配效率低**：买家很难快速找到符合自己需求的商品
- **缺乏信任机制**：交易双方缺乏有效的信用评价体系

### 1.2 项目定位

本项目旨在开发一个**基于AI的校园二手交易智能推荐平台**，在普通二手交易平台基础上：
1. 引入**AI拍照识物**功能，自动识别商品品类、品牌、成色，简化发布流程
2. 引入**智能推荐系统**，基于用户行为数据进行个性化推荐，提升匹配效率
3. 预留**Agent-Skill-MCP接口**，支持AI助手通过自然语言查询商品和推荐结果
4. 实现**完善的权限管理**，通过RBAC模型保障系统安全

### 1.3 技术栈

- **前端**：Vue 3 + Element Plus + Vite
- **后端**：Flask + SQLAlchemy
- **数据库**：MySQL（改造前为SQLite）
- **推荐算法**：协同过滤 + 矩阵分解（ALS）+ 内容推荐
- **AI服务**：图像识别（可选，初期Mock）

## 二、用户角色与权限设计（RBAC）

### 2.1 角色定义

本系统设计三种用户角色：

| 角色 | 说明 | 权限范围 |
|------|------|---------|
| 普通用户 | 注册用户，平台主要使用者 | 注册、登录、发布商品、浏览、搜索、下单、评价、查看推荐 |
| 平台管理员 | 平台运营管理人员 | 管理用户、审核/下架商品、查看操作日志 |
| Agent服务账号 | AI助手专用服务账号 | 通过Skill调用商品查询、推荐查询（只读权限） |

> **说明：** Agent服务账号也存储在user表中，通过`user_type`字段区分，完全纳入RBAC权限体系。

### 2.2 RBAC权限模型

系统采用标准的RBAC（Role-Based Access Control）模型，包含五张核心表：

**【图片位置1：在此处插入"用例图"】**

> 说明：展示三种角色及其可执行的所有用例

**数据库表结构：**

1. **user**（用户表）
   - 存储用户基本信息
   - `user_type`字段区分三种角色类型

2. **role**（角色表）
   - 定义系统角色（normal_user, admin, agent_service）
   
3. **permission**（权限表）
   - 定义系统权限（product:view, product:publish, user:manage等）
   
4. **user_role**（用户-角色关联表）
   - 实现用户与角色的多对多关系
   
5. **role_permission**（角色-权限关联表）
   - 实现角色与权限的多对多关系

### 2.3 安全机制

- **密码加密**：使用BCrypt算法对密码进行加密存储
- **数据脱敏**：API接口返回的手机号进行脱敏处理（如：138****5678）
- **操作日志**：记录管理员和Agent的关键操作，便于审计
- **权限校验**：每个接口调用前进行权限验证

## 三、功能性需求

### 3.1 User Story（8条核心需求）

1. **US-001 用户账号管理**
   - 作为普通用户，我可以注册、登录、维护个人信息。

2. **US-002 AI拍照识物**
   - 作为普通用户，我可以拍照识物，自动填充商品品类、品牌、成色。

3. **US-003 商品发布管理**
   - 作为普通用户，我可以发布、编辑、下架自己的商品。

4. **US-004 商品浏览搜索**
   - 作为普通用户，我可以浏览、搜索商品，并用自然语言筛选（如"300元以内九成新手机"）。

5. **US-005 智能推荐**
   - 作为普通用户，我可以查看首页个性化推荐和商品详情页的相似推荐。

6. **US-006 交易流程**
   - 作为普通用户，我可以加入购物车、创建订单、模拟支付、评价商品。

7. **US-007 平台管理**
   - 作为平台管理员，我可以管理用户、审核/下架违规商品、查看操作日志。

8. **US-008 Agent接口调用**
   - 作为Agent服务账号，我可以通过Skill查询商品与推荐结果，且只能查询不能修改删除。

### 3.2 三条核心业务线

**业务线1：用户账号线**
- 用户注册 → 登录认证 → 个人信息管理 → 角色权限控制

**业务线2：商品发布线**
- 拍照识物（AI自动识别）→ 填充商品信息 → 发布/编辑商品 → 商品上下架

**业务线3：商品浏览与交易线**
- 浏览商品 → 搜索筛选 → 查看推荐 → 加入购物车 → 创建订单 → 支付 → 评价

## 五、推荐模块设计（核心重点）

### 5.1 推荐目标

- **首页推荐**：为每个用户推荐"猜你喜欢"的商品列表
- **详情页推荐**：在商品详情页推荐相似商品
- **搜索排序**：在搜索结果中进行个性化排序

### 5.2 数据来源

推荐系统基于用户行为数据，包括：
- **浏览行为**：用户查看商品详情
- **收藏行为**：用户收藏商品
- **加购行为**：用户将商品加入购物车
- **下单行为**：用户购买商品
- **评价行为**：用户对商品进行评分和评论

所有行为数据统一存储在`user_behavior`表中，通过`behavior_type`字段区分。

### 5.3 推荐算法设计

**【图片位置3：在此处插入"推荐算法流程图"】**
> 文件名：`03_推荐算法流程图.png`  
> 说明：展示四种推荐策略的完整决策流程

系统设计**四种推荐策略**，根据用户状态自动选择：

#### 策略A：无偏好用户 → 全局热门推荐
- **适用场景**：新用户未设置兴趣品类，无历史行为
- **算法逻辑**：按商品热度（behavior_count）降序排序
- **实现方式**：
  ```sql
  SELECT * FROM products 
  WHERE status='approved' 
  ORDER BY behavior_count DESC 
  LIMIT N
  ```

#### 策略B：有偏好无行为 → 基于内容推荐
- **适用场景**：用户设置了兴趣品类，但无历史行为记录
- **算法逻辑**：根据用户偏好品类，推荐该品类下的高分商品
- **实现方式**：
  ```python
  preferred_categories = user.get_preferred_categories_list()
  products = query_by_categories(preferred_categories, order_by='score')
  ```

#### 策略C：少量行为 → 轻量混合推荐
- **适用场景**：用户行为数量 < 10（数据稀疏）
- **算法逻辑**：70% 基于偏好品类 + 30% 基于历史行为相似商品
- **实现方式**：
  ```python
  # 70%：偏好品类高分商品
  category_items = recommend_by_categories(preferred_categories, limit=0.7*N)
  
  # 30%：历史行为相似商品
  behavior_items = recommend_by_history(user_behaviors, limit=0.3*N)
  
  # 合并去重
  result = merge_and_deduplicate([category_items, behavior_items])
  ```

#### 策略D：充足行为 → ML模型推荐
- **适用场景**：用户行为数量 ≥ 10（数据充足，可训练模型）
- **算法逻辑**：协同过滤 + 矩阵分解（ALS）+ 内容推荐混合
- **实现步骤**：
  1. **构建用户-商品行为矩阵**：rows=用户，cols=商品，values=行为权重
  2. **ALS矩阵分解**：分解为用户隐向量和商品隐向量，预测评分
  3. **内容过滤**：基于商品品类、价格、成色计算相似度
  4. **混合打分**：60% 协同过滤分数 + 40% 内容相似度分数
  5. **排序返回**：按综合分数降序返回Top N
  
- **使用工具**：scikit-surprise库（ALS算法）

### 5.4 冷启动策略

**新用户冷启动**：
- 引导用户设置兴趣偏好（弹窗选择品类）
- 优先推荐全局热门商品
- 快速积累用户行为数据

**新商品冷启动**：
- 基于内容推荐：推荐给偏好该品类的用户
- 给予新商品一定的曝光权重
- 监控新商品的点击率和转化率

### 5.5 评价指标

- **准确率（Precision）**：推荐商品中用户感兴趣的比例
- **召回率（Recall）**：用户感兴趣的商品中被推荐的比例
- **覆盖率（Coverage）**：推荐系统能覆盖的商品比例
- **多样性（Diversity）**：推荐列表中商品的多样性

## 八、Agent-Skill-MCP方案设计

### 8.1 设计目标

为AI助手（如ChatGPT、Claude等）提供调用平台能力的标准化接口，使AI助手能够：
- 通过自然语言查询商品信息
- 获取个性化推荐结果
- 帮助用户筛选符合条件的商品

### 8.2 Skill能力清单

| Skill名称 | 功能说明 | 典型场景 |
|-----------|----------|----------|
| product_query | 商品查询 | "帮我找300元以内的手机" |
| recommendation_query | 推荐查询 | "给我推荐几款适合学生的商品" |
| nl_filter | 自然语言筛选 | "九成新、100-200元的保温杯" |
| product_recognize | 商品识别 | 上传图片识别商品信息 |

### 8.3 安全约束

1. **独立服务账号**：Agent使用专用账号（user_type=agent_service）
2. **只读权限**：Agent只能查询（SELECT），不能修改（INSERT/UPDATE/DELETE）
3. **操作留痕**：所有Agent请求记录日志（trace_id、时间戳、参数）
4. **参数强校验**：对所有输入参数进行严格验证，防止SQL注入
