# 校园二手交易平台 - 需求文档

**版本：** V1.0  
**日期：** 2026年10月  

---

## 一、项目背景与选题说明

校园二手交易平台存在信息分散、发布麻烦、买家找不到合适商品的问题。本项目在普通二手平台基础上，引入 **AI 拍照识物**辅助发布、**智能推荐**提升匹配效率，并预留 **Agent-Skill-MCP** 能力，做成一个 Web 前后端分离的中等规模业务系统。

**技术栈：** Vue 3 + Flask + MySQL + 推荐算法（协同过滤 + 矩阵分解）

---

## 二、用户角色与权限（RBAC）

### 2.1 三种角色

| 角色 | 说明 |
|------|------|
| 普通用户 | 注册、登录、发布商品、浏览、搜索、下单、评价 |
| 平台管理员 | 管理用户、审核/下架商品、查看日志 |
| Agent 服务账号 | 通过 Skill 调用商品查询、推荐查询，只读 |

> Agent 服务账号也存于 user 表，用 user_type 字段区分，纳入 RBAC 权限体系。

### 2.2 RBAC 五张表

- **user**（用户表）
- **role**（角色表）
- **permission**（权限表）
- **user_role**（用户-角色关联表）
- **role_permission**（角色-权限关联表）

**安全机制：**
- 密码 BCrypt 加密，手机号脱敏返回
- 记录管理员与 Agent 关键操作日志

## 三、功能性需求（8 条 user story）

1. 作为普通用户，我可以注册、登录、维护个人信息。
2. 作为普通用户，我可以拍照识物，自动填充商品品类、品牌、成色。
3. 作为普通用户，我可以发布、编辑、下架自己的商品。
4. 作为普通用户，我可以浏览、搜索商品，并用自然语言筛选。
5. 作为普通用户，我可以查看首页个性化推荐和商品详情相似推荐。
6. 作为普通用户，我可以加入购物车、创建订单、模拟支付、评价。
7. 作为平台管理员，我可以管理用户、审核/下架违规商品、查看操作日志。
8. 作为 Agent 服务账号，我可以通过 Skill 查询商品与推荐结果，且只能查询不能修改删除。

---

## 四、三条业务线

- **业务线1：** 用户账号（注册、登录、个人信息、角色权限）
- **业务线2：** 商品发布与识物（拍照识物 → 自动填充 → 发布/编辑/下架）
- **业务线3：** 商品浏览与推荐（浏览、搜索、自然语言筛选、智能推荐、下单、评价）

## 六、推荐模块设计（核心重点）

### 6.1 推荐目标
- **首页推荐**："猜你喜欢"商品列表
- **详情页推荐**：相似商品推荐
- **搜索排序**：个性化排序

### 6.2 数据来源
用户行为数据：浏览、收藏、加购、下单、评价（存储在 user_behavior 表）

### 6.3 四种推荐策略

**【图片位置3：在此处插入"推荐算法流程图"】**
> 文件名：`03_推荐算法流程图.png`  
> 说明：展示四种推荐策略的完整决策流程

#### 策略A：无偏好用户 → 全局热门
- **适用：** 新用户未设置兴趣品类
- **排序：** 按行为数（收藏+评价+下单）降序
- **实现：** `SELECT * FROM products ORDER BY behavior_count DESC`

#### 策略B：有偏好无行为 → 基于内容
- **适用：** 设置了偏好品类但无历史行为
- **推荐：** 根据用户选定品类推荐高分商品

#### 策略C：少量行为 → 轻量混合
- **适用：** 行为数 < 10
- **组合：** 70%基于偏好品类 + 30%基于历史高分品类

#### 策略D：充足行为 → ML模型
- **适用：** 行为数 >= 10
- **算法：** ALS矩阵分解 + 内容推荐混合
- **步骤：**
  1. 构建用户-商品行为矩阵
  2. ALS矩阵分解预测评分
  3. 内容过滤（品类、价格相似度）
  4. 混合打分：60%协同 + 40%内容
  5. 排序返回 Top N
- **工具：** scikit-surprise 库

### 6.4 冷启动策略
- **新用户：** 引导设置偏好 → 推热门商品
- **新商品：** 基于内容推荐给偏好该品类的用户

### 6.5 评价指标
准确率、召回率、覆盖率、多样性

## 九、Agent-Skill-MCP 方案

### 9.1 Skill 能力清单
- **product_query**：商品查询（"帮我找300元以内的手机"）
- **recommendation_query**：推荐查询
- **nl_filter**：自然语言筛选（"九成新100-200元的保温杯"）
- **product_recognize**：商品识别（上传图片）

### 9.2 安全约束
1. **独立服务账号**：user_type=agent_service
2. **只读权限**：只能查询，不能修改删除
3. **操作留痕**：所有请求记录日志（trace_id、时间戳）
4. **参数强校验**：防止 SQL 注入
