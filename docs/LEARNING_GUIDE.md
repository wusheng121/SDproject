## 你需要掌握的内容（面向大三同学 / 课程项目）

这份指南的目标：让你能**看懂项目骨架**、能**独立把骨架补成可用系统**、并且能在答辩时讲清楚“为什么这么设计”。

### 1. 项目整体架构（你要能画出来）

- **浏览器（Vue 页面）**  
  - 负责：页面展示、表单交互、调用后端 API
- **后端（Flask API）**  
  - 负责：鉴权、业务逻辑、数据库读写、返回 JSON
- **数据库（SQLite）**  
  - 负责：持久化用户、电影、收藏、评分等数据

数据流（最常见面试/答辩题）：
- 用户在前端点击按钮 → `axios` 发请求到 `/api/...`
- Flask 路由函数接收请求 → 调用 service / 操作模型 → 写/读 SQLite
- Flask 返回 JSON → 前端更新页面状态（Pinia / 组件 state）

### 2. REST API 基础（必须掌握）

你要会解释这些词：
- **HTTP 方法**：GET（查）、POST（增/提交）、PUT/PATCH（改）、DELETE（删）
- **状态码**：200/201 成功，400 参数错，401 未登录，403 无权限，404 不存在，500 服务端异常
- **统一响应结构**：前端好处理，后端好排错

建议你用 Postman / Apifox / 浏览器 Network 面板做接口调试。

### 3. Flask 你必须懂的点

- **Blueprint（蓝图）**：把路由按模块拆开（用户、电影、交互）
- **配置管理**：开发/生产的差异（debug、数据库地址、密钥）
- **CORS**：跨域问题；开发阶段通常用 CORS 或 Vite 代理解决

你需要会回答：为什么要用蓝图？  
答：模块化、可维护、可测试，后续接口变多不会一团乱麻。

### 4. SQLAlchemy / 数据库你必须懂的点

- **模型(Model) = 表**：类的字段 = 表的列
- **关系(Relationship)**：
  - 电影-类型、电影-演员：典型多对多（用中间表）
  - 用户-收藏、用户-评分：一对多（或用唯一约束保证“同一用户对同一电影唯一”）
- **索引与唯一约束**：提高查询速度 / 防止重复数据

你需要会解释：为什么收藏/评分要加 `(user_id, movie_id)` 唯一约束？  
答：避免重复收藏、避免同一电影多条评分导致平均分计算混乱。

### 5. Vue 3 你必须懂的点

- **单文件组件(SFC)**：`<template> + <script setup> + <style>`
- **路由(Vue Router)**：7 个页面如何切换、如何做动态路由 `/movies/:id`
- **状态管理(Pinia)**：登录态（token、用户信息）放哪里
- **组件化**：比如 `MovieCard` 复用

### 6. 开发阶段最容易踩坑的 6 件事（建议背下来）

- **跨域**：前端 5173，后端 5000 → 用 Vite 代理或 Flask-CORS
- **密码不可明文存储**：必须 hash（`werkzeug.security`）
- **登录 token 存储位置**：localStorage 易用但有 XSS 风险；课程项目可先用它
- **分页**：电影列表一定要分页，否则数据多了页面卡
- **错误处理**：后端返回 code/message，前端统一弹出提示
- **时间字段**：created_at / updated_at 很有用，调试/展示都方便

### 7. 你如何把“骨架”补成“可演示系统”（建议里程碑）

- **M1：跑通页面与接口**  
  - 前端能打开 7 个页面  
  - 后端 `/api/health`、`/api/movies` 能返回 mock 数据

- **M2：数据库落地**  
  - 注册/登录写入 User 表  
  - movies 列表/详情从 Movie 表读出

- **M3：交互功能完成**  
  - 收藏：写 Favorite 表  
  - 评分：写 Rating 表，详情页展示平均分

- **M4：推荐功能（简化版也可以）**  
  - 规则推荐：按“你常收藏/常评分的类型”给 TopN  
  - 或热门推荐：全站评分最高/收藏最多

### 8. 你答辩时应该准备的材料

- 系统截图：7 个页面各 1 张
- ER 图（或实体关系说明）
- 接口列表（请求参数 + 响应示例）
- 推荐策略解释（哪怕是简单规则，也要讲清楚“输入/输出/依据”）
