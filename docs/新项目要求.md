# 校园二手交易平台——新项目要求说明

## 一、项目定位

把现有的电影推荐系统改造成“AI 拍照识物与智能推荐的校园二手交易平台”。

- 系统类型：Web 前后端分离业务系统
- 核心功能：用户注册登录与 RBAC 权限、商品发布与浏览、智能推荐、AI 拍照识物、自然语言筛选、管理员审核
- 技术栈：Vue 3 + Flask/FastAPI + MySQL（把原 SQLite 换成 MySQL）
- 复用原则：最大化复用现有电影推荐系统的前后端和推荐算法，只改数据模型和页面语义

## 三、三种角色

| 角色 | 说明 |
|---|---|
| 普通用户 | 注册、登录、发布商品、浏览、搜索、下单、评价、查看推荐 |
| 平台管理员 | 管理用户、审核/下架商品、查看操作日志 |
| Agent 服务账号 | 通过 Skill 调用商品查询、推荐查询，只读，不能修改删除 |

Agent 服务账号也存于 user 表，用 user_type 字段区分，纳入 RBAC 权限体系。

---

## 四、8 条 user story

1. 作为普通用户，我可以注册、登录、维护个人信息。
2. 作为普通用户，我可以拍照识物，自动填充商品品类、品牌、成色。
3. 作为普通用户，我可以发布、编辑、下架自己的商品。
4. 作为普通用户，我可以浏览、搜索商品，并用自然语言筛选。
5. 作为普通用户，我可以查看首页个性化推荐和商品详情相似推荐。
6. 作为普通用户，我可以加入购物车、创建订单、模拟支付、评价。
7. 作为平台管理员，我可以管理用户、审核/下架违规商品、查看操作日志。
8. 作为 Agent 服务账号，我可以通过 Skill 查询商品与推荐结果，且只能查询不能修改删除。

## 五、三条业务线

- 业务线1：用户账号（注册、登录、个人信息、角色权限）
- 业务线2：商品发布与识物（拍照识物 → 自动填充 → 发布/编辑/下架）
- 业务线3：商品浏览与推荐（浏览、搜索、自然语言筛选、智能推荐、下单、评价）

---

## 六、推荐模块设计思路（核心，重点保留）

- 推荐目标：首页猜你喜欢、商品详情相似推荐、搜索页个性化排序
- 数据来源：用户浏览、收藏、加购、下单、评价行为
- 算法设计：
  - 内容推荐：基于商品品类、品牌、成色、价格区间推荐相似商品
  - 协同过滤：基于用户-商品行为矩阵，找相似用户推荐
  - 矩阵分解：用隐向量预测用户偏好
  - 混合策略：冷启动用内容推荐，数据充足后用协同过滤 + 矩阵分解
- 冷启动：新用户推热门商品，新商品推内容相似
- 评价指标：准确率、召回率、覆盖率

## 七、数据库改造要求

### 从电影推荐系统改造：
| 原表 | 新表 | 说明 |
|---|---|---|
| movie | product | 电影 → 商品，字段改为：标题、描述、价格、成色、分类、图片、发布者 |
| rating | user_behavior | 评分 → 用户行为，字段改为：用户id、商品id、行为类型（浏览/收藏/加购/下单/评价）、时间 |
| user | user | 保留，新增 user_type 字段区分普通用户/管理员/Agent服务账号 |

### 新增 RBAC 五张表：
- user（用户表）
- role（角色表）
- permission（权限表）
- user_role（用户角色中间表）
- role_permission（角色权限中间表）

### 新增业务表：
- order（订单表）
- review（评价表）
- cart（购物车表）
